# 동시 방문자 부하 시험 (로컬, 2026-10-25)

"동시 사용자가 100명이면 어디가 먼저 무너지나"에 답하려고, 공개 데모 방문자가 하는 일을 그대로 하는 가상 방문자를 로컬 서버에 단계별로 붙였습니다. 공개 서버(Render)에는 돌리지 않았습니다. 시간당 한도를 실제 방문자와 같이 쓰기 때문입니다. 원자료는 [load-local.json](evaluation/load-local.json)에 있고, 표의 값은 모두 거기서 옮겼습니다.

## 무엇을 했나

- **서버.** `render.yaml`의 시작 명령과 같게 `scripts/setup.py` 뒤 uvicorn 프로세스 하나(디스패처 포함)를 띄웠고, provider는 규칙 엔진뿐입니다. 데이터베이스는 같은 기계의 PostgreSQL 16.2(pgvector, 개발 의존성 `pgserver`)이고 설정마다 새 데이터베이스를 썼습니다.
- **방문자 한 명**(`scripts/load-test.py`)은 브라우저 화면(`web/src/main.tsx`)과 같은 순서로 부릅니다.
  1. 체험 공간을 엽니다(`POST /api/demo-sessions`). 새 테넌트에 도면 20장과 청구 8건이 들어갑니다.
  2. 문서 목록과 선택된 도면의 PNG 하나를 받습니다.
  3. 화면의 기본 검사(브래킷, 구멍 간격 40 mm, SUS304)를 두 번 합니다. 검사마다 `POST /api/runs`를 보내고, 화면처럼 1초마다 실행과 이벤트를 읽으며 끝날 때까지 기다립니다.
- **단계.** 1, 10, 25, 50, 100, 150명입니다. 도착은 단계의 처음 10초에 고르게 퍼뜨렸습니다. 각 단계가 "한 시간 안에 이만큼 온다"가 되도록 단계 전에 시간당 한도 칸을 비웠습니다. 방문자마다 다른 `X-Forwarded-For` 주소를 보내 주소당 한도가 사람마다 따로 걸리게 했습니다(uvicorn은 127.0.0.1에서 온 이 머리글을 믿습니다).
- **한도는 기본값 그대로입니다.** 체험 공간은 시간당 전체 100개·주소당 20개, 실행은 시간당 200개, 테넌트당 동시 실행 3개입니다. 디스패처 칸은 2개, 미리 데운 worker는 1개, 데이터베이스 연결 풀은 8개입니다.
- **잰 것.** 요청마다 지연과 응답 코드를 쟀습니다. 429는 설계된 거절이라 5xx·연결 오류와 따로 셉니다. 큐 대기는 실행의 `queued` 이벤트에서 worker가 쓴 `started` 이벤트까지입니다. 서버 메모리는 API 프로세스와 worker 자식 프로세스의 PSS 합이고, 데이터베이스는 넣지 않았습니다.
- **기계.** CPU 4개, 메모리 15.7 GiB, Python 3.12.11입니다.

## 찾아서 고친 것

처음 잰 코드(`0a42db8`)에서는 50명에서 검사 한 번이 중앙값 7.5초, 100명에서 44.6초였습니다. 실행 하나의 일은 그때도 0.1초였습니다.

원인은 디스패처였습니다. 디스패처는 실행을 동시에 둘까지 돌리고, 새 실행이 등록되거나 1초가 지나야 깨어납니다. 끝난 실행은 아무것도 깨우지 않아서, 빈 칸이 다음 등록이나 다음 폴링까지 놀았습니다. 이제 실행이 끝나면 디스패처를 깨웁니다(`9352146`, 테스트 `tests/unit/test_dispatcher.py`). 0.05초짜리 실행 여섯 개를 한 번의 등록 신호로 넣으면 고치기 전에는 2.07초, 고친 뒤에는 0.2초 안에 끝납니다.

미리 데운 worker를 둘로 늘린 설정(`FITWITNESS_WARM_WORKERS=2`)도 나란히 쟀습니다. worker가 하나뿐이면 두 번째 칸은 실행마다 새 Python 프로세스를 띄웁니다. 아래는 검사 한 번 p50 / p95이고, 괄호 안은 큐 대기 p50입니다.

## 100명에서 남은 병목

worker를 늘려도 줄지 않는 큐 대기 11초는 API 프로세스 하나에서 옵니다.

- 100명 단계에서 그 프로세스의 CPU는 중앙값 80%, p95 106%입니다. Python 한 프로세스가 한 코어를 다 쓰는 상태입니다. 디스패처도 같은 프로세스 안의 스레드라 HTTP 처리와 같은 CPU를 나눠 씁니다.
- 초당 85개 요청 가운데 87%가 화면의 1초 폴링(실행과 이벤트, 두 개씩)입니다.
- 공간 열기는 중앙값 3.5초, p95 6.8초입니다. 도면 20장의 PDF·PNG·STEP·mesh와 청구 서류를 테넌트마다 새로 씁니다. 문서 목록은 중앙값 1.1초입니다.

줄이는 방법으로는 폴링 대신 변경을 밀어 주는 방식, uvicorn 프로세스 여러 개(이 경우 디스패처를 한 곳에서만 돌려야 함), 체험 공간의 씨앗 자료를 테넌트마다 복사하지 않는 것을 생각할 수 있습니다. 셋 다 아직 하지 않았습니다.

## 이 숫자가 말하지 않는 것

- **한 기계에서 잰 값입니다.** 데이터베이스가 같은 기계에 있어 질의 왕복이 거의 0입니다. 공개 서버는 Render 무료 인스턴스(메모리 512 MB, 공유 CPU)이고, 데이터베이스는 다른 서비스(Neon)라 질의마다 왕복이 있습니다([WORKFLOW.md](WORKFLOW.md)). 이 표를 공개 서버의 용량으로 옮기면 안 됩니다. 공개 서버의 CPU는 이 기계보다 훨씬 작아서 같은 지점에서 더 일찍 막힐 것으로 보지만, 재지는 않았습니다.
- **메모리.** 서버 메모리 최대는 100명 361 MiB, 150명 396 MiB입니다(PSS, 프로세스별 RSS 합으로는 432·467 MiB). 512 MB 인스턴스에 가깝습니다. 공개 서버에서 재지는 않았습니다.
- **모델을 부르지 않습니다.** 규칙 provider라 실행 하나가 0.1초입니다. 모델 경로를 켜면 실행 하나가 수 초라([COST.md](COST.md)) 칸 두 개가 훨씬 먼저 찹니다. 공개 데모는 유료 모델을 부르지 않으므로 공개 데모의 조건은 이쪽입니다.
- **방문자는 모두 같은 일을 합니다.** 실제 방문자는 더 띄엄띄엄 누르고, 평가 탭이나 청구 탭을 열기도 합니다.
- **변동.** 설정마다 기록한 것은 한 번씩입니다. 기록하기 전에 고치기 전 기본 설정을 같은 방식으로 세 번 더 돌렸습니다. 기록한 한 번까지 네 번에서 50명의 큐 대기 중앙값은 7~15초, 100명은 40~48초로 흔들렸습니다. 고치기 전 worker 2 설정은 한 번 더 돌렸고, 그때는 50명 3.0초, 100명 19.2초였습니다.
- **연결 끊김.** 고치기 전 150명 단계에서 응답 없이 끊긴 연결이 3건(worker 2에서 1건) 있었습니다(`RemoteProtocolError`, `ReadError`). 서버 로그에는 오류가 없었고 원인은 확인하지 않았습니다. 고친 뒤에는 0건입니다.
- **확인한 위험(2026-10-26, 아님).** uvicorn(0.54)은 `FORWARDED_ALLOW_IPS`가 없으면 127.0.0.1과 ::1에서 온 `X-Forwarded-For`만 믿고, `render.yaml`은 그 값도 `--forwarded-allow-ips`도 주지 않습니다. 그래서 Render 앞단 프록시 뒤에서는 주소당 20개 한도가 프록시 주소 하나에 걸릴 수 있다고 봤습니다. 공개 서버의 `fw_admission`을 보니 그렇지 않았습니다. 서버는 방문자의 공개 주소를 세고 있었고, 검사한 클라우드 컨테이너의 주소 해시가 그대로 나왔습니다. [DEPLOYMENT.md](DEPLOYMENT.md#2026-10-26-배포)

## 다시 재는 방법

```bash
# 서버: render.yaml과 같은 시작 명령 (FITWITNESS_DATABASE_URL은 로컬 데이터베이스)
PYTHONPATH=src python scripts/setup.py
PYTHONPATH=src uvicorn fitwitness.api.app:create_app --factory --host 127.0.0.1 --port 8787

# 방문자 (설정 C. worker 2 설정은 서버를 FITWITNESS_WARM_WORKERS=2로 띄움)
PYTHONPATH=src python scripts/load-test.py --steps 1,10,25,50,100,150 --checks 2 --ramp 10 \
  --dsn "$FITWITNESS_DATABASE_URL" --reset-admission --server-pid <uvicorn pid> \
  --label "C: defaults, finished run wakes the dispatcher" --output docs/evaluation/load-local.json
```

`--reset-admission`은 서버 데이터베이스의 시간당 한도 칸을 지우므로 로컬에서만 씁니다. 스크립트는 `onrender.com` 주소를 거부합니다.
