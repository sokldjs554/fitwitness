## 들은 말

**1. 정상 청구에서 제일 먼저 보는 것.** 지급 금액보다 계약 상태와 청구한 담보입니다. 보험기간 안의 사고인지, 그 특약이 보장하는 항목인지, 이전 지급 이력이 있는지부터 봅니다. 그다음 환자 이름, 진단명, 입퇴원 날짜, 수술 여부를 서류끼리 대조하고, 지급액이 약관대로 계산됐는지 봅니다. 추출한 값과 원본 위치를 연결해 주는 것은 좋고, 근거를 찾는 시간을 줄일 수 있겠다고 했습니다. 다만 "화면에 표시되는 '지급 완료'가 내부 원장에 기록된 상태인지, 실제 은행 송금까지 완료된 상태인지는 구분해 줬으면" 한다고 했습니다.

**2. 화면에 없지만 실제로 꼭 확인하는 것.** 계약의 부담보·감액 조건, 특약 변경 이력, 보험수익자와 지급 계좌의 일치 여부. 진단비는 진단서만으로 판단하기 어려운 건이 있습니다(암 진단비는 조직검사 결과가 필요한 경우도 있고, 수술비는 수술명과 수술기록을 약관의 수술 분류표에 대조해야 할 수도 있음). 금액만 보여 주지 말고 어떤 약관과 서류를 근거로 나온 금액인지 확인할 수 있어야 한다고 했습니다.

**3. 한도 초과와 2인 승인.** 금액이 커지면 승인 단계를 더한다는 방향은 납득이 됩니다. 다만 회사마다 상품·담보·사고 유형에 따라 전결 기준이 달라서 데모의 금액이 "현실적인 공통 기준이라고 보기는 어렵다"고 했습니다. 금액이 낮아도 진단 내용이 불분명하거나 면책 판단이 필요한 건은 사람이 봐야 하고, 서류와 조건이 명확한 건은 금액만이 아닌 별도 기준을 적용할 수 있다고 했습니다. "담당자 이름만 다르게 입력해 2인 승인을 처리하는 건 실제 운영에서는 부족"하고, 직원 계정과 승인 권한을 확인하고 누가 어떤 근거로 승인했는지 기록해야 한다고 했습니다.

**4. 서류 누락과 중복 청구.** 서류가 빠졌다고 바로 부지급으로 끝내지 않고, 부족한 서류를 확인해 보완을 요청하고, 추가로 낸 서류를 기존 건에 연결해 심사를 이어갑니다. "승인과 부지급 외에 '서류 보완 요청'이라는 선택지가 필요"하다고 했습니다. 같은 내용이 접수됐다고 무조건 중복 지급 대상이 아니고, 이미 지급한 건인지, 기존 청구의 추가 서류인지, 금액 정정 청구인지 봐야 합니다. 같은 날 수술이라도 서로 다른 수술일 수 있고, 진단코드가 비슷하다고 같은 청구가 아닙니다. 지급 이력 자동 확인은 유용하지만 동일 사고·동일 담보의 판단 기준은 더 세분화해야 한다고 했습니다.

**5. 스캔 읽기 예시 다섯 건.**
- 그대로 읽어 자동 지급(CLM-00000): OCR이 맞다는 것과 지급 요건을 충족했다는 것은 별개이니 계약과 담보 확인이 끝나 있어야 한다.
- 틀린 코드를 확대해 다시 읽음(CLM-00045): 의심되는 부분만 다시 읽는 방식은 업무에 도움이 된다. 다만 원본에서 실제로 K인지 확인할 수 없다면 재인식 결과만 믿고 넘기면 안 된다.
- 글자를 자리에 맞게 보정(CLM-00012): 실용적이다. 다만 금액을 계산해 맞추는 것과 원문 값을 임의로 고치는 것은 구분해야 하고, "원본 인식값과 보정값을 둘 다 남겨야 나중에 확인할 수 있다".
- 못 읽은 값은 사람에게(CLM-00039): 적절하다. 진단코드 첫 글자가 보장 여부나 금액을 바꿀 수 있어 추측하면 안 된다.
- 스캔으로 읽은 값만으로는 거절을 확정하지 않음(CLM-00006): 좋은 방향이다. 다만 담당자가 원본을 보고 판단하도록 어떤 조항에 걸렸는지도 같이 보여 줘야 한다.

**6. 사람이 서류를 보는 순서.** 서류 종류·발급기관·환자 정보가 맞는지 먼저 보고, 진단명·진단일·입퇴원 기간·수술명을 대조한 다음 약관의 지급 조건에 해당하는지 판단합니다. 지금 화면은 OCR의 정답 여부를 보기에는 좋지만 심사자가 서류 전체를 검토하는 흐름은 더 보완해야 한다고 했습니다.

**7. 실제 서류가 합성 서류와 다른 점.** 병원마다 양식이 다르고, 직인·의사 서명·여러 쪽의 진료기록이 있습니다. 사진은 접히거나 그림자가 지고, 팩스는 글자가 뭉개집니다. "수술확인서에 보험약관상 1~5종 수술 등급이 정확히 적혀 있을 거라고 가정하면 안" 되고, 수술명과 수술일을 보고 보험회사가 그 계약의 분류표로 판단해야 할 수 있습니다. 진료비 영수증의 합계는 실제 지출액이고 입원일당·수술비·진단비 같은 정액 담보의 지급액과는 다르니 구분이 분명해야 한다고 했습니다.

**8. 자주 틀리거나 비는 칸.** 질병분류기호, 입퇴원 날짜, 진단 확정일, 수술명과 수술일, 금액. 질병분류기호의 영문·숫자 혼동(0과 O·D·Q)은 자동으로 다른 글자로 바꾸지 않는 게 맞다고 했습니다. 수술 분류가 서류에 없을 때 곧바로 고객에게 서류를 다시 요청하지 말고 수술명과 약관으로 확인할 수 있는지 먼저 보라고 했습니다.

**9. 자동 지급해도 되는 건과 사람이 봐야 하는 건.** 자동: 계약·담보가 유효하고, 필요한 증빙이 충분하고, 지급 이력과 중복에 문제가 없고, 약관에 따른 계산이 명확하고, 지급 계좌 확인 같은 지급 전 통제가 끝난 건. 사람: 서류 내용이 서로 다르거나, 진단코드·수술명 해석이 불명확하거나, 면책·감액에 걸리거나, 중복이 애매한 건, 고액과 예외적인 사고. "OCR 신뢰도가 0.7 이상이라고 무조건 자동 지급하는 식은 위험"하고 지급 결정에 중요한 항목은 개별로 확인해야 한다고 했습니다.

**10. 지급 직전에 AI가 다시 보고 이상하면 담당자에게만 넘기는 방식.** **조건부로 쓰겠다**고 했습니다. 놓친 서류 불일치나 계산 문제를 잡아 준다면 도움이 됩니다. 다만 AI가 지급 여부를 단독으로 정하거나 금액을 바꾸게 하지는 않겠고, 의심되면 지급을 보류하고 담당자에게 근거를 보여 주는 방식이 적절하다고 했습니다. 왜 문제라고 봤는지 원본의 어느 부분과 어떤 약관을 근거로 했는지 바로 볼 수 있어야 하고, 정상 청구까지 지나치게 많이 붙잡으면 오히려 일이 늘어나니 도입 전에는 잘못된 지급을 얼마나 막는지와 함께 정상 건을 불필요하게 붙잡는 비율도 확인해야 한다고 했습니다.

**11. 돕는 곳 / 방해하는 곳.** 돕는 곳: 값을 찾고, 원본 위치를 잇고, 적용한 기준과 처리 이력을 한 화면에서 보는 것. 반복적인 서류 대조에는 쓸 여지가 있습니다. 방해하는 곳: 실제 약관·계약 정보와 연결되지 않은 상태의 "지급 가능" 결과는 그대로 믿기 어렵습니다. 담당자 확인의 이유만 보여 주고 그 뒤의 서류 보완이나 재심사를 진행할 방법이 없으면 다른 시스템을 다시 열어야 합니다.

**12. 제일 먼저 바꾸라고 한다면.** **서류 누락 건에 '보완 요청' 기능부터.** 담당자 확인 뒤 승인 또는 부지급만 고르는 구조 대신 보완 요청, 심사 보류, 재심사, 최종 지급·부지급을 구분하고, 부족한 서류를 안내하고 다시 접수된 서류를 기존 청구에 붙여 심사를 이어가는 기능이 있으면 실제 업무 흐름에 가까워진다고 했습니다. 그다음은 실제 상품별 약관 기준, 수술 분류 판단, 중복 청구 구분, 승인자 권한 인증입니다. 맺는 말: 값과 지급 판단 근거를 연결하는 방향은 좋지만, 실제 심사에 쓰려면 정확히 읽는 기능보다 "지급을 보류하고, 서류를 보완하고, 담당자가 책임 있게 최종 결정할 수 있는 절차"가 더 중요하다고 했습니다.
